## Configuration as reported

- Python: executable path indicated Python 3.14.
- Local backend: Ollama `qwen3:14b` (reported installed size ~9.3 GB).
- Extractor: `hybrid` (rules first, Ollama fallback), configured default `temperature=0`.
- Dataset: `benchmarks/text_v04.jsonl` (8 development, 12 held-out test sentences).
- Comparison: `rules` baseline on the 12 test sentences.
- Device allocation, CPU/GPU utilization, loaded weights hash, prompt token counts, thermal conditions and model cold/warm state: **not measured**.

|---|---|---:|---:|---:|---:|---:|---:|---:|---:|

**Interpretation:** The local hybrid pipeline did *not* improve the measured test accuracy over deterministic rules. Seven test facts were not extracted exactly and one labeled nonfact was not abstained from. The slow hybrid latency includes fallback execution and potentially initial model loading; it is not a controlled energy or throughput comparison. The perfect development result is not evidence of out-of-template generalization. This small hand-authored dataset cannot establish general-purpose model performance.

## Follow-up: one-case trace from local `qwen3:14b`

The user subsequently reran the unchanged model/prompt on **case `t03` only**,
after adding route diagnostics via [PR #7](https://github.com/anasshallabi/adaptive-cognitive-memory/pull/7):

| Field | Observed |
| --- | --- |
| Input | `Zentra is considered a car brand.` |
| Route | `fallback` (local Ollama) |
| Expected original benchmark label | `Zentra is_a car brand` |
| Parsed model response | `None` (`abstained`) |
| Extraction error | None |
| Local runtime | 9,806.651 ms |

This rules out the theory that the rules or question guard, rather than
Ollama, skipped `t03`. **It does not reveal why Qwen3 abstained.**

Crucially, the original label may oversimplify the semantics of
"is considered a", which can be an attributed classification rather
than an unconditional fact. Do not silently relabel or modify the
held-out evaluation in response to this observation. We created a
**post-hoc diagnostic**, with different direct/attributed/hedged
sentences, to test this hypothesis but not to claim an independent
generalization improvement. See [claim modality design note](MODALITY.md).

## Second follow-up: direct versus attributed model-only probe

The user then ran `python -m examples.probe_text --model qwen3:14b --case direct --case attributed` on Windows. The results were:

| Probe | Rule parser | Local Qwen3 14B (model-only) | LLM processing time |
| --- | --- | --- | ---: |
| `Zentra is a car brand.` | `is_a` extracted | abstained, 0 errors | 9,893.406 ms |
| `Zentra is considered a car brand.` | abstained | abstained, 0 errors | 8,254.882 ms |

**Correction to the earlier hypothesis:** ambiguity from "is considered"
cannot by itself explain the model's abstention, because it also
abstained from the direct, unambiguous sentence. We have no basis to
attribute the cause to Qwen3's understanding, a particular hidden
reasoning trace, the extraction prompt, schema generation or a runtime
setting without further experiments.

### Next isolated variable

Ollama documents an optional `think` setting on `/api/chat`;
`think: false` asks supported models to skip their reasoning phase.
The existing ACM code did not send this option, so it used Ollama's
model default. A **new post-hoc probe** compares that default with
explicit `think: false` for the *same* two fictional sentences.

This comparison **must not be described as a fresh held-out accuracy
improvement**. No updated model-only probe outputs or timings have
been observed yet. The original t03 dataset label is also unchanged.

| Ollama model load duration | 2,678,545,300 ns |
| Prompt tokens | 168 |
| Generated tokens | 35 |
| Model evaluation duration | 963,975,000 ns |

The model also abstains on an unambiguous direct assertion when
thinking is disabled. Thus disabling thinking **did not fix** extraction.
This single timing observation cannot by itself establish an overall
performance gain from disabling thinking because the previous run
had different load state and conditions.

### Isolating the extraction instructions

The next **post-hoc control** preserves the same model, JSON schema and
`think=false` while changing only the **system extraction instruction**
from the original strict instruction to a literal-claim instruction. The
alternative clarifies that recording what a sentence *claims* is not the
same task as verifying real-world truth, and contains one made-up example.
It must still reject nonclaims and uncertain sentences.

```powershell
git pull origin main
python -m examples.probe_text --model qwen3:14b --think off --prompt literal --case direct
```

Any improvement on this already-observed probe is **exploratory debugging,
not held-out generalization**. A fresh independently annotated test set
is required for a scientific claim.

## Diagnostic questions (unresolved)

1. Which of the failed cases went through `rules`, `guard`, or `fallback`? The first version did not log that.
2. Did the fallback model return `status=abstain`, a syntactically valid but non-matching claim, or a string span variation?
3. Is the current prompt overly conservative, or are test cases genuinely ambiguous?
4. Does `ollama` mode outperform `hybrid` on the same sentences?
5. How do warmup, prefill, tokenizer/think mode, memory and GPU deployment influence cost?

These questions **must be answered before modifying rules or prompts using the held-out test data**. After inspecting test failures, make a **new independent test set** before claiming any subsequent gain.

## Scientific status

The system currently performs fact extraction with an **already pretrained** LLM and stores structured claims in a graph. This is neither one-shot concept induction from scratch nor evidence of reduced computation. Negative findings are part of the public experimental record.
