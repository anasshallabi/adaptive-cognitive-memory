# ACM v0.5 — First local evaluation on new synthetic sentences

**Recorded:** 2026-09-30  
**Evidence:** User-provided Windows PowerShell console output, `qwen3:14b` locally through Ollama; results from a manifest that was frozen on GitHub before this local execution.  
**Caution:** Model inference was not independently rerun by GitHub CI. These 40 sentences were authored by the project assistant, not independently collected or annotated, and do not represent general-purpose language comprehension.

## Frozen configuration

```powershell
python -m examples.compare_text --dataset benchmarks/text_v05.jsonl --extractor hybrid --model qwen3:14b --think off --prompt literal --split dev --summary
python -m examples.compare_text --dataset benchmarks/text_v05.jsonl --extractor hybrid --model qwen3:14b --think off --prompt literal --split test
```

Other hardware/application measurements (model quantization, Ollama version, GPU VRAM consumption, exact load warmth and temperature) were not recorded.

## Observed outputs

| Metric | Development | Test |
| --- | ---: | ---: |
| Number of examples | 12 | 28 |
| Exact accuracy | **12/12 (100%)** | **13/28 (46.43%)** |
| Extraction precision | 1.0 | 0.428571 |
| Recall | 1.0 | 0.5 |
| F1 | 1.0 | 0.461538 |
| Correct abstention on annotated nonclaims | 100% | **4/10 (40%)** |
| Technical extraction errors | 0 | 0 |
| Total measured extraction latency | 5,714.670 ms | 8,513.154 ms |

Crucial qualification: the **development score did not test successful
LLM extraction of new positive facts**. Of the twelve development inputs:
six direct claims were matched by rules; five other sentences caused
correct LLM fallback abstentions; and a question was rejected by a
guard. Thus 12/12 on development does *not* predict performance on
novel affirmative wordings.

### Test route attribution

| Route | Inputs processed | Exactly correct | Incorrect |
| --- | ---: | ---: | ---: |
| Existing regex rules | 15 | 7 | **8** |
| Local Qwen3 fallback | 12 | 5 | **7** |
| Question guard | 1 | 1 | 0 |
| **Total** | **28** | **13** | **15** |

Of 18 inputs annotated as containing one valid claim, nine were
extracted exactly; of 10 inputs annotated as requiring abstention, only
four were rejected.

### Error anatomy (all 15 incorrect items)

| Category | Case IDs | What happened |
| --- | --- | --- |
| Determiners omitted by model | t04, t08 | Model extracted `cartes électroniques` or `moteurs électriques` rather than required `des ...`. These are *strict exact-span* errors, not necessarily invalid semantic relationships. |
| Model abstained on direct present claims | t05, t06, t07 | No stored relation for `owns`, `détient`, `runs on`. |
| Rule parser produced noncanonical subject | t14, t16, t17, t18 | Rules retained descriptions/adverbs such as `agence nommée`, `La société`, `currently`, or `organisation appelée` as part of subject instead of a canonical entity label. |
| Rule parser misclassified nonclaims | t20, t23, t24, t26 | Attribution, command, two-clause statement, attribution were treated as direct categorical facts. **Unsafe for automatic memory writes.** |
| Model flattened time/compound statements | t21, t25 | Past fact (t21) or multi-part historical/identity sentence (t25) was converted into one unqualified current claim. Note that the annotation policy is intentionally restrictive: t25 does contain an identity description but should abstain because its overall structure carries historical qualification. |

Nothing in the run establishes that an already pretrained Qwen3 14B
can reliably learn *new concepts* from a single observation. It can
sometimes extract a source claim, and sometimes mistakes what was
asserted. Storage into the current graph is not verified truth.

### Scientific interpretation

- **The biggest immediate failure is false automatic memory writes**:
  the existing high-priority regex parser can return a syntactically
  valid but semantically wrong triple *without ever asking the LLM*.
- Local fallback also misses affirmative paraphrases and can flatten
  temporal information; replacing all regex rules with one LLM does
  not automatically guarantee reliability.
- The long and short timings cannot be directly compared with earlier
  v0.4 runs as controlled compute gains. Cold-start, warm model state,
  GPU utilization, model/token count and task difficulty differ.
- This original synthetic benchmark is small, intentionally designed
  and fully visible on GitHub. It cannot support population-level or
  human-like cognition claims.

## Next experiment (post-hoc)

An opt-in `ConservativeHybridExtractor` introduces a **limited
deterministic pre-memory admission gate**. It rejects common questions,
directives, attributions, possibilities, historical expressions and
multi-proposition sentences **before the rule parser can silently
store them**, and falls back to a model for unclear multiword subjects.

This guard is a transparent **heuristic**, neither general natural
language understanding nor exhaustive injection protection. It may
over-abstain or let unsupported structures through. It was designed
**after viewing the 28 test outcomes**; any re-run on
`benchmarks/text_v05.jsonl` becomes a *post-hoc diagnostic*,
**not an independent proof of improvement**.

The original `rules` and `hybrid` configurations and 13/28 baseline
remain unchanged. See [v0.6 conservative admission gate](CONSERVATIVE_GATE.md)
and the previous [v0.4 results](RESULTS_V04_2026-09-30.md).
